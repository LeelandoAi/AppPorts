# 上线前迁移引导审视

当前 APFS 容器迁移已经有目标磁盘格式、加密和空间检查。主要问题在于入口按技术方案命名、用户需要在多个页面之间自行拼接流程，以及签名检查把不确定结果当成了确定异常。

面向首次使用者，建议主线保持为：**选择应用 → 选择要迁移的内容 → 选择存储 → 查看检查结果 → 开始迁移 → 验证使用**。APFS 是软件根据数据类型选择的方法，用户需要理解的是占用空间、外置盘依赖和恢复方式。

## 迁移入口

应用行直接提供「迁移应用」和「迁移数据」两个可见动作。点击「迁移数据」直接选中这个应用的数据页，不要求右键、双击或先去另一页选择磁盘。现有目录行保留直接操作，避免让每一次迁移都经过完整向导。

首次进入应用数据时，可以先显示内容摘要：应用本体大小、可迁移数据大小和需要连接的外置盘。数据目录的用途、完整路径和迁移方法放在详情中。识别不了用途的目录如实显示路径；共享容器应提示可能涉及其他应用，不自动勾选所有目录。

不要按「符号链接 / APFS 挂载 / 重签名」让普通用户选择方案。默认模式根据数据类型选择；经典模式保留在高级设置中，并持续显示当前模式。软件尚未上线，无需把旧模式兼容说明作为每个新用户的第一课。

实机核对发现，原有模糊匹配把 Trae CN 中的「CN」当作前缀，连带匹配了 WPS 的 `cn.wps.wpslaunchhelper` 容器，修复面板也因此要求还原无关目录。本次已排除地区、平台和版本等通用词，并增加回归测试。更完整的后续工作仍应区分精确归属、共享容器与名称推测，避免把所有匹配结果当成确定归属。

## 操作前检查

检查结果应同时回答「能不能迁移」和「现在做什么」，并保留刚才选的应用、目录和磁盘。

| 检查结果 | 用户看到的下一步 |
| --- | --- |
| 还没选择存储 | 当场选择，选完继续当前目录的检查 |
| 磁盘未连接 | 连接后重新检查，或换一个位置 |
| 目标不是 APFS | 说明仅容器数据需要 APFS；可换盘，或将这部分数据留在本机 |
| APFS 已加密 | 说明当前方案不能保持加密保护；不引导关闭加密来强行迁移 |
| 空间不足 | 显示需要和可用的空间，允许减少所选内容或换盘 |
| 应用正在运行 | 指明要退出哪个应用，退出后继续检查 |
| 权限不足 | 打开对应系统设置；返回后继续当前任务 |
| 可以迁移 | 展示迁移内容、目标盘、释放空间估算、外置盘使用要求，再提供开始按钮 |

现有 `MountMigrationPreflight` 已实现磁盘检查，应该复用。后续将运行状态和权限检查也纳入同一面板，可以减少连续弹框。格式转换说明保留在可选帮助中，不作为默认主按钮。

## 签名：检测恢复需要，避免引导再次重签名

**默认的 APFS 容器迁移不需要重签名。** 不应因为应用来自 App Store、存在容器目录、迁移过或者启动失败，就把它判定为需要重签名。

| 证据 | 状态和操作 |
| --- | --- |
| 原始备份是开发者签名，真实应用现在明确为 Ad-hoc | 已确认签名替换，提供恢复引导 |
| 签名检查超时、失败，或真实外置应用不可读 | 待检查，允许重试并保留恢复材料；不显示为已修好或已替换 |
| 应用原本就是 Ad-hoc | 不能据此判定为开发者签名被替换 |
| 没有 AppPorts 的历史记录 | 不应推断是 AppPorts 修改了签名；启动故障另行诊断 |
| 当前是开发者签名 | 不属于 Ad-hoc 替换告警；完整修复还要检查签名有效性和正常启动 |

检查必须解析真实 `.app`，不能检查本地启动壳后把结果归给外置应用。签名备份在操作前就会生成，因此「有备份」本身也不能证明重签名已经成功。

macOS 27 的启动兼容性风险和签名是否被替换应分开表达。沙盒身份可能在旧重签名过程中被移除，不能仅靠当前 entitlements 判断应用过去是否为沙盒应用。具体应用能否启动还需要实际验证，不应把风险提示写成所有应用必然故障。

更完整的后续诊断可以区分「有效开发者签名 / Ad-hoc / 未签名 / 无效 / 无法检查」，但签名验证失败仍不能直接触发重签名。优先引导恢复完整备份或安装官方版本。

## 修复引导

先处理旧容器符号链接，再恢复原始应用。已经使用 APFS 挂载迁移的目录不需要只为签名修复而还原。

修复方式按恢复材料区分：完整原始应用备份可直接恢复真实应用；旧的身份记录需要同版本官方原版或官方重装。只有准备覆盖安装且本地只是启动入口时，才要求先把应用迁回本机。

「现在还能打开」允许用户稍后处理，但不代表恢复完成。修复后要重新验证签名，并从 Finder / Dock 启动、检查数据访问。现有恢复事务会校验内容是否匹配；应用已经更新或被修改时，会要求提供匹配的官方原版。后续还应在界面明确展示恢复来源与版本。

后续建议让修复面板在恢复或迁回完成后自动回到当前应用，继续显示下一步。当前操作仍会关闭面板并复用已有恢复流程，这部分还没有做成连续向导。

## 本次已落实

- 默认目录行入口统一为「迁移」；经典模式中保留明确的方法区分。
- 在数据页直接选择外部存储；换盘后继续检查当前目录，不必再次寻找并点击它。
- 检查说明突出迁移目的和保留签名，APFS 方法放到详情；移除断盘后必然无损恢复的绝对承诺。
- 为签名检查失败增加独立的待检查状态、检查入口和恢复入口，保留备份。统一使用真实应用解析规则。
- 修复应用模型的相等性比较，让签名状态变化能刷新列表。
- 排除应用名中的通用词匹配，修正 Trae CN 把 WPS 容器列入还原步骤的问题。
- 完整备份恢复不再受「先迁回本机」的界面步骤约束；覆盖安装的准备动作放到对应分支。
- macOS 27 文档八种语言均将修复前移，优先图形界面操作，命令行收进可展开的进阶说明；区分当前开发版本与正式发布。

统一的应用级迁移入口、用途摘要、合并权限检查和修复后自动续接，是进一步的产品改版建议。本次没有替换迁移引擎，也没有上线发布文档。

- 89 项测试通过，涵盖应用及目录扫描、签名检测、修复过程的运行状态检查、磁盘预检和本地化。
- Release clean build 通过，版本为 1.8.2（build 15），严格代码签名验证通过；已打开此构建。
- 原生界面确认 Trae CN 的目录从误匹配的 13 项变为自身的 3 项，修复面板自动跳过无关的容器还原；官方重装分支按需展开且左对齐。
- 八种语言的文档构建通过；修复均为正文第一个二级章节，相关页内链接检查无失效项。
- 界面验证未执行真实应用的数据迁移、还原或重签名。
