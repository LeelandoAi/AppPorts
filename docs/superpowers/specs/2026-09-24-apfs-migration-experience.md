# APFS 迁移稳定性与用户引导

用户目标：不用理解卷、分区和挂载机制，也能判断是否需要切换；现有正常工作的配置可以保留；AppPorts 的内部数据卷尽量不出现在 Finder 中。2026-09-24 用户授权自主完善代码、应用及文档翻译，验证后按功能提交到 main。

## 已核实的问题与实现顺序

1. **签名恢复**：旧版本只保存身份名称，无法恢复原始文件。保存完整原版应用，在工作副本中签名、校验并交换；恢复不需要开发者私钥。旧备份可选择同版本官方原版补救。手动操作前停止后台旧重签任务及其子进程，避免恢复被撤销。
2. **并发操作**：DataDirsView 四个挂载操作拿不到 OperationLock 后仍继续。改为中止并给出重试提示；不得绕过锁。
3. **卷身份**：只检查路径是挂载点不够。挂载、自动重挂、卸载、还原均核对实际卷 UUID，不操作占用该路径的其他卷。
4. **Finder**：创建内部卷用 `-nomount` 避免初次自动出现在 /Volumes；所有 AppPorts 挂载请求使用 `nobrowse`。不改 Finder 全局偏好，不隐藏用户原来的外置盘。系统插盘时可能先自动挂载，不能承诺任何时刻都不会短暂出现；磁盘工具中仍可管理卷。
5. **加密**：diskutil addVolume 默认不加密，不继承同容器其他卷的加密。识别已加密外置卷，禁止悄悄降级成未加密数据卷；未完成自动解锁和密码管理前，给出明确的暂不支持说明及保留原状路径。
6. **记录损坏**：读取失败不能在下一次写入时当成空记录覆盖；保留文件并阻止新增或删除记录，提示恢复记录。
7. **回滚及清理**：失败不能删除唯一数据副本。挂载位置和卷身份必须在破坏性操作前复核，失败材料保留；未完成清理不得以完全完成误导用户。

## 引导方案

采用操作时出现的状态引导。首次启动强制格式向导会打断只迁移应用本体的用户；仅提供文档链接又无法告诉用户当前该怎么选，因此两者不作为主要入口。

### 入口

- 欢迎页、准备情况：明确 APFS 仅影响沙盒容器数据的新迁移方式，不影响已能使用的应用迁移与普通目录。
- 应用数据页：提供「了解迁移方式」入口，当前存储和旧迁移状态决定初始内容。
- 点击迁移容器数据：先只读检查当前盘，之后展示针对当前状态的步骤；未经通过的条件不能以「继续」启动迁移。
- 已迁移用户：不自动改目录、签名、盘格式；提示可关闭，遇到需要修复时从应用行重新进入。

### 状态及文案方向

| 状态 | 核心解释 | 首要操作 | 其他操作 |
|---|---|---|---|
| 未选择外置存储 | 先选择存放数据的位置，暂不改变磁盘 | 选择外部存储 | 暂不迁移 |
| 普通 APFS | 可直接迁移，不需要抹盘；现有文件保留 | 迁移此目录 | 查看具体变化 |
| exFAT / NTFS / HFS+ | 此方式需要 APFS；现在可以继续使用现有磁盘 | 选择另一块 APFS 存储 | 查看准备方法、保留现状 |
| 加密 APFS | 新数据卷不会继承当前卷密码，当前版本不做加密降级迁移 | 保留现状 | 查看说明 |
| 旧符号链接容器 | 先还原对应容器数据，再恢复原始签名，最后迁移 | 从当前未完成的步骤开始 | 以后处理 |
| 外置盘断开或卷未就绪 | 数据仍在外置盘，先连接并等待；不要新建账号或目录 | 重新检查 / 重新挂载 | 打开诊断说明 |

### 执行前确认

面向用户显示应用名、数据大小、目标盘、将释放的空间；说明不会抹盘、不会重签应用、首次启动需允许访问外置存储、使用时需连接外置盘。详细路径与 APFS 技术解释放在可展开说明中。主按钮使用「迁移数据」，不用泛化的「继续」。

### 完成及日常使用

成功显示「数据已移至外部存储」，给出打开应用验证的下一步与还原入口。平时用「已连接」「等待外置存储」表达状态；内部卷名、UUID、命令参数只在诊断中出现。保留系统必须展示的授权框，不伪装为完全无权限操作。

### exFAT 说明

优先推荐保留旧盘、另选 APFS 卷。APFS 容器可共享剩余空间，通常不用重分区。exFAT/NTFS 不能用 macOS 自带工具无损缩小；已有未分配空间才可直接另建分区，否则应备份后重新分区，或使用支持对应格式缩容的工具。不要声称 Windows 自带工具能无损缩小 exFAT；是否支持需按文件系统及工具核实。应用不自动抹盘、不自动缩分区。

## 本地化与文档

新增及修改的应用文案覆盖当前 22 种语言，不能用英文冒充其他语言的完成翻译。文档覆盖现有 8 个语言站点，并同步导航、链接及与代码相关的操作说明。中文是内容基准，其他语言的功能、限制和数据保护承诺保持一致。历史版本记录说明当时行为，当前操作指南反映修复后的行为。

## 验收

- 真实开发者签名应用临时副本可重签并恢复签名、授权和文件内容；损坏、更新、失败重试、旧备份、并发后台覆盖有回归测试。
- APFS 测试覆盖隐藏参数、拒绝加密降级、外来卷占位、记录损坏、锁超时和错误回滚；所有磁盘变更测试使用假磁盘或专用临时介质，不接触用户真实数据。
- 不把假磁盘测试声称为 Finder 真机验收；若无法创建测试磁盘映像，明确记录未实测范围。
- 引导状态有确定性测试；所有入口、取消和返回行为可用；中文与至少英文界面检查。
- 本地化目录完整、占位符一致，文档构建成功，Release clean build 和相关测试通过。
- 按功能形成可追踪提交，最终 main 包含已验证修改，不混入未确认的外部改动。
