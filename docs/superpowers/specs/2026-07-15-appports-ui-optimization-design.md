# AppPorts UI/UX 优化设计

日期：2026-07-15

状态：已实现，待发布前复核

目标版本：下一功能版本

## 背景

AppPorts 1.8.0 已经具备完整的应用迁移、数据目录迁移和自定义目录迁移能力。当前 UI 的主要问题不是功能缺失，而是随着功能增加，顶部工具区、列表行和设置入口逐渐承载了过多信息，影响操作辨识度、macOS 原生感、键盘可用性和大列表滚动性能。

本次改造保持现有迁移逻辑、数据模型和最低 macOS 12.0 部署目标不变，重点改善界面结构、操作语义、可访问性和渲染性能。

## 方案比较

### 方案 A：渐进式原生化改造（采用）

保留当前三个主功能及应用页的左右双栏结构，分阶段替换顶部工具区、设置入口、危险操作和数据目录交互。macOS 13+ 使用更合适的原生容器，macOS 12 保留兼容回退。

优点：风险可控、可以逐步验证，不需要重写迁移业务逻辑。

缺点：部分旧结构会在过渡期继续存在。

### 方案 B：完整导航架构重做

将三个主功能改为统一侧边栏，并全面采用 `NavigationSplitView`、Inspector 和 Table。

优点：信息架构最统一，长期扩展性最好。

缺点：macOS 12 需要维护两套结构，改动面大，容易影响现有多选和双栏迁移工作流。

### 方案 C：仅做视觉微调

只调整颜色、字号、圆角和间距，不改变导航与控件结构。

优点：开发量最小。

缺点：无法解决顶部拥挤、危险操作语义、键盘可达性和渲染热路径问题。

采用方案 A，在稳定现有功能的前提下获得大部分用户体验收益。

## 设计目标

1. 首次引导只在首次启动时出现，并准确表达权限状态。
2. 危险操作必须使用正确图标、破坏性语义和确认流程。
3. 主导航、搜索、排序、刷新与设置更符合 macOS 工具栏习惯。
4. 数据目录页降低单行信息密度，保留专业信息但不让其抢占主要操作。
5. 所有可点击元素具备键盘和 VoiceOver 语义。
6. 列表行渲染不得执行同步文件系统读取。
7. 继续支持 macOS 12.0，所有 macOS 13+ 结构提供回退。

## 非目标

- 不修改应用、数据目录或自定义目录的迁移算法。
- 不改变外部目录布局或现有 UserDefaults 键的含义。
- 不引入第三方依赖。
- 不采用仅适用于 macOS 26 的 Liquid Glass API。
- 不在本轮重写整个应用架构或强制采用特定 MVVM 目录结构。

## 详细设计

### 1. 首次引导

- 使用 `@AppStorage("hasCompletedOnboarding")` 保存完成状态。
- 未完成时显示 `WelcomeView`；完成后直接进入主界面。
- 主按钮文案根据权限状态变化：
  - 已具备所需访问能力：`开始使用`
  - 未具备：`稍后设置并继续`
- 权限卡本身不伪装成按钮；仅“打开系统设置”是真正的 `Button`。
- 使用可滚动布局和语义字体，避免长语言或小屏幕裁切。

### 2. 主窗口与工具栏

- 保留应用、数据目录、目录迁移三个主区域。
- 第一阶段继续使用紧凑分段导航，但将其封装成独立组件并使用原生 `Picker` 语义。
- 搜索使用 `.searchable` 或具备 `Cmd+F` 焦点能力的原生搜索字段。
- 排序、刷新和设置放入 SwiftUI `.toolbar`。
- 数据目录专属控件只在数据目录页显示；“迁移后重签名”不再与主导航竞争空间。
- WindowGroup 增加合理的默认大小、统一工具栏样式和最小尺寸约束。

### 3. 设置

- 在 App Scene 中增加原生 `Settings` Scene，自动支持 `Cmd+,`。
- 设置按主题分区：
  - 通用：App Store/非原生应用迁移策略。
  - 签名：迁移后重签名、登录时自动重签名。
  - 日志：启用状态、最大大小、查看、导出与清空。
- 清空日志使用破坏性按钮和确认弹窗。
- 移除重复的“最大日志大小”标签。
- 主界面设置入口使用 `SettingsLink`（macOS 14+）或 `openSettings`/兼容入口。

### 4. 应用列表

- 保留左右对等的 `HSplitView`，因为本地与外部应用是同级工作区，而不是主从导航。
- 列表行主要层级为：图标与名称、状态、大小。
- 断开链接不再使用 `link.badge.plus`；改用 `link.badge.minus` 或 `trash`。
- 破坏性动作默认放入右键菜单；需要常驻时仅在悬停或选中状态出现。
- 状态徽章使用稳定枚举 ID。
- 锁定状态、框架类型和签名状态在扫描阶段计算并传入行视图，视图渲染阶段不执行 `stat` 或文件读取。

### 5. 数据目录

- 工具目录继续使用分组列表，但每行只突出名称、大小、状态和主要动作。
- 路径为次级信息；说明文字放入帮助提示、详情区域或选中后的 Inspector。
- 优先级颜色只用于重要/警告辨识，普通状态与普通操作使用中性色。
- 应用数据页在 macOS 13+ 使用 `NavigationSplitView`：左侧应用，右侧数据目录；macOS 12 保留 `HSplitView` 回退。
- 左侧应用选择通过 `List(selection:)` 或 `Button` 完成，不使用 `onTapGesture` 模拟控件。
- 树形目录行使用可访问的选择控件，并保留子级稳定身份。

### 6. 可访问性与字体

- 所有交互元素使用 `Button`、`Toggle`、`Picker`、`List(selection:)` 等原生控件。
- 仅在确实需要坐标或点击次数时使用 `onTapGesture`。
- 主要内容优先采用 `.headline`、`.body`、`.callout`、`.caption` 等语义字体。
- 装饰性图标从辅助功能树隐藏；状态和动作提供明确标签与提示。
- 选中态同时使用形状、图标或文字表达，不能只依赖颜色。

### 7. 主题

- 删除工程中指向不存在资源的全局 `AccentColor` 名称设置，明确采用用户的系统强调色。
- 主要选择态与普通主操作使用系统强调色，确保适配用户偏好、深色模式和提高对比度设置。
- 破坏性、警告、成功颜色保留系统语义；普通按钮不再使用多种固定高饱和色。

### 8. 状态与组件边界

- 不进行全面架构重写，但拆分以下独立区域：
  - `MainNavigationControl`
  - `AppsWorkspaceToolbar`
  - `DataDirectoriesToolbar`
  - `ApplicationPane`
  - `DataDirectoryBrowser`
- 将列表扫描结果、选择状态和弹窗状态按功能区收敛，避免单个 View 同时持有四十余个状态值。
- 迁移服务和扫描 actor 保持现有接口；仅在必要时增加预计算的展示字段。

## 错误与安全处理

- 所有删除、断链、清空日志操作在执行前显示明确的结果说明。
- 仅视觉变化不应改变已有迁移条件判断。
- 设置迁移期间保持向后兼容，已有 UserDefaults 值继续生效。
- macOS 13+ API 必须通过 `#available` 或独立兼容容器提供 macOS 12 回退。

## 验证计划

### 自动验证

- 使用外置 Xcode：`/Volumes/hano/Applications/Xcode.app/Contents/Developer`。
- 每个代码修改批次后执行 Debug build。
- 完成后执行 Release clean build。
- 用户可见文案修改后运行 `LocalizationAuditTests`。
- 涉及设置键或扫描展示字段时运行相关单元测试。

### 界面验证

- 当前系统深色模式下检查欢迎页、三个主功能、设置和关于页。
- 检查默认窗口和最小窗口宽度。
- 检查长应用名、长路径和空列表状态。
- 通过辅助功能树确认主要控件均可聚焦并具有正确角色。
- 检查大应用列表滚动时不再触发同步文件读取。

## 实施顺序

1. 首次引导、危险操作、徽章稳定身份与文件 I/O 移出渲染路径。
2. 原生 Settings Scene、设置内容整理、Accent Color。
3. 主工具栏与搜索整理。
4. 数据目录行密度与选择语义优化。
5. macOS 13+ `NavigationSplitView` 和 macOS 12 回退。
6. 状态拆分、构建测试、运行时视觉复核与独立代码审查。

## 完成标准

- 欢迎页不会在完成引导后重复出现。
- 破坏性操作图标、文案、按钮角色和确认流程一致。
- 设置可通过 `Cmd+,` 打开，且不存在重复标签。
- 主要导航、搜索、刷新和设置不再挤在自定义内容栏中。
- 数据目录选择和可点击徽章可通过键盘与 VoiceOver 操作。
- 应用列表行渲染路径不包含文件系统读取，徽章身份稳定。
- Debug、Release 构建及相关测试通过。
- 当前仓库运行版本的关键界面完成实际截图或可访问性树验证。
