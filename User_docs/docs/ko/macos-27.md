# macOS 27 업그레이드 안내

::: tip 핵심 내용
AppPorts로 WeChat 등의 컨테이너 데이터를 옮기며 재서명에 동의했다면 macOS 27로 업그레이드한 뒤 앱이 이중 클릭 직후 종료될 **수 있습니다**. WeChat은 해당되지만 QQ Music 등은 시험에서 계속 열렸습니다. **데이터는 손상되지 않았으며** 다시 마이그레이션할 필요도 없습니다. 데이터를 이 Mac으로 복원하고 공식 경로에서 앱을 재설치하면 복구됩니다. 이후에도 외장 드라이브에 두려면 새 [마운트 마이그레이션](/ko/datamigrae/mount-migration)을 사용하세요.
:::

## 영향을 받는 경우

| 항목 | 설명 |
|------|------|
| 발생 조건 | macOS 27로 업그레이드 |
| 대상 앱 | `~/Library/Containers/` 또는 `~/Library/Group Containers/` 데이터를 옮기고 Ad-hoc 재서명한 앱, 또는 우클릭 메뉴로 수동 재서명한 샌드박스 앱 |
| 대표 증상 | Finder / Dock에서 이중 클릭해도 반응이 없고 아이콘만 잠깐 나타났다 사라짐. 오류 창은 없음. 모든 재서명 앱이 그런 것은 아니며 같은 27에서 QQ Music은 정상 실행 |
| 데이터 | 채팅 기록과 로그인 상태를 포함해 온전함 |
| 확인된 사례 | WeChat 4.1.15, macOS 27.0 (26A428) |

간단히 말해 재서명이 앱의 샌드박스 신원을 제거했기 때문입니다. macOS 27이 앱의 컨테이너 접근 자격을 확인할 때 이전 서명의 권한 기록이 이미 저장돼 있으면 새 서명이 일치하지 않아 거부됩니다. WeChat 로그에는 `Failed to match existing code requirement`가 나옵니다. QQ Music처럼 이전 기록이 없는 앱은 현재 허용되지만 키체인 로그인 상태 등 이미 잃은 권한이 복구되는 것은 아닙니다. 원리는 [컨테이너 데이터, 샌드박스와 서명 신원](/ko/datamigrae/container-identity)을 참고하세요.

## 업그레이드 전 확인

다음 스크립트는 AppPorts가 서명을 교체한 앱을 나열합니다. 출력된 앱은 업그레이드 후 문제가 생길 수 있습니다.

```bash
BACKUP_DIR="$HOME/Library/Application Support/AppPorts/signature-backups"
for plist in "$BACKUP_DIR"/*.plist; do
  [ -f "$plist" ] || continue
  original=$(/usr/libexec/PlistBuddy -c "Print :signingIdentity" "$plist" 2>/dev/null)
  app=$(/usr/libexec/PlistBuddy -c "Print :originalPath" "$plist" 2>/dev/null)
  case "$original" in ""|ad-hoc) continue ;; esac   # 本来就是 ad-hoc 的跳过
  [ -d "$app" ] || continue
  if codesign -dv "$app" 2>&1 | grep -q "Signature=adhoc"; then
    printf "%s\n    原始签名: %s\n" "$app" "$original"
  fi
done
```

업그레이드 전에 아래 [복구](#복구)를 마치는 것이 좋습니다. 최소한 목록을 기록해 두면 업그레이드 후 무엇을 확인해야 하는지 알 수 있습니다.

## 업그레이드 후 증상 확인

```bash
# 1. 签名（出现 Signature=adhoc 且 TeamIdentifier=not set 即已被重签名）
codesign -dv --verbose=4 /Applications/WeChat.app 2>&1 | grep -E "Authority|TeamIdentifier|Signature"

# 2. 复现并看系统日志
open -a /Applications/WeChat.app; sleep 3
log show --last 1m --style compact 2>/dev/null | grep -i "rejected approval request"
```

2단계에 `kTCCServiceSystemPolicyAppData ... denied`가 나오면 확인됩니다. 더 자세한 점검표는 [컨테이너 데이터, 샌드박스와 서명 신원](/ko/datamigrae/container-identity#직접-확인)에 있습니다.

## 복구

AppPorts 1.8.2는 이런 앱을 자동으로 찾아 목록에 빨간색 ‘서명 교체됨’ 배지를 표시하고 시작 시 한 번 알립니다. 우클릭 메뉴의 ‘복구 단계 보기’를 선택하면 아래 순서대로 단계별 상태와 버튼을 표시하는 패널이 열립니다. 전 과정에서 데이터를 삭제하지 않습니다. 수동 처리도 같은 순서이며 **순서를 바꾸면 안 됩니다**.

### 1단계: 컨테이너 데이터를 이 Mac으로 복원

복구 패널에서 ‘모두 복원’을 누르세요. 또는 ‘데이터 디렉토리’ → ‘앱 데이터’에서 해당 앱을 선택하고 ‘연결됨’ 상태의 컨테이너 디렉토리를 하나씩 ‘복원’하세요. 앱 자체가 열리지 않으므로 실행 중 검사에 막히지 않습니다.

먼저 해야 하는 이유는 재설치한 앱이 정상 샌드박스 앱으로 돌아가 심볼릭 링크 뒤의 데이터를 읽지 못하기 때문입니다. 건너뛰면 재설치해도 빈 화면이라 복구되지 않은 것처럼 보입니다.

복원 후 다음과 같이 확인할 수 있습니다.

```bash
find ~/Library/Containers/<Bundle ID> -maxdepth 6 -type l -exec readlink {} \; 2>/dev/null
# 没有输出，或输出里没有 /Volumes/... 就对了
```

### 2단계: 실제 앱을 이 Mac으로 다시 이동

실제 앱이 외장 드라이브로 옮겨진 경우에만 필요합니다. 이때 `/Applications`에는 AppPorts의 실행 껍데기만 있습니다. 그 위에 설치하면 껍데기를 덮어써 외장 사본이 연결을 잃습니다. 복구 패널에서 ‘이 Mac으로 다시 이동’을 누르거나 ‘외부 드라이브’에서 앱을 선택해 같은 버튼을 누르세요. 설치 후에도 외장 드라이브에 두고 싶으면 실제 앱을 다시 옮기면 됩니다.

### 3단계: 앱 재설치 — 열리지 않을 때만 필요

27에서 정상적으로 열린다면 이 단계는 건너뛰고 4단계에서 데이터를 마운트 마이그레이션으로 바꿔도 됩니다. 재설치가 필요하면 앱을 완전히 종료한 뒤 공식 경로에서 덮어 설치하세요. App Store 앱은 App Store를 사용하며 패널에 ‘App Store 열기’ 버튼이 있습니다. 그 외 앱은 공식 사이트에서 받으세요. **컨테이너 디렉토리를 삭제하지 마세요.** 재설치가 건드리지 않으므로 채팅 기록과 로그인 상태가 남습니다.

설치 후 패널에서 ‘다시 확인’을 누르거나 첫 번째 점검 명령으로 `Authority=Developer ID Application: ...` 또는 `Apple Mac OS Application Signing` 서명인지 확인하세요. 서명이 돌아오면 ‘서명 교체됨’ 배지가 사라집니다. 일반 스캔은 백업을 보존하며 AppPorts를 통해 복원을 완료한 뒤에만 해당 백업을 정리합니다.

::: tip 전체 백업은 직접 복원할 수 있고 이전 백업에는 원본 앱이 필요합니다
새 ‘원본 서명 복원’은 원본 앱 전체 백업을 사용하므로 개발자 개인 키가 필요 없습니다. 서명 신원 이름만 있는 이전 기록은 여전히 직접 복원할 수 없습니다. 같은 버전의 공식 원본 `.app`을 선택하거나 위 절차대로 재설치하세요. 어느 방법이든 클래식 모드의 컨테이너 데이터를 먼저 복원해야 합니다. [서명 백업과 복원](/ko/datamigrae/resign#서명-백업과-복원)을 참고하세요.
:::

### 4단계(선택): 마운트 마이그레이션으로 데이터를 외장 드라이브에 다시 저장

재설치 후 AppPorts를 열면 컨테이너 디렉토리에 ‘마이그레이션’ 대신 ‘마운트 마이그레이션’이 표시됩니다. 누르고 안내를 따르세요. 앱을 처음 열 때 시스템이 이동식 볼륨 접근 권한을 요청하면 **허용하세요**. 외장 드라이브는 암호화되지 않은 APFS여야 합니다. AppPorts가 먼저 검사하고 다음 단계를 안내합니다. APFS가 아니라면 데이터를 이 Mac에 그대로 두어도 괜찮습니다. [외장 드라이브가 APFS여야 하는 이유](/ko/why-apfs#what-to-do)를 참고하세요.

## 도움이 되지 않는 방법

| 방법 | 효과가 없는 이유 |
|------|-----------|
| 데이터만 복원하고 해결됐다고 생각하기 | 복원은 외장 데이터 접근 문제만 해결하며 서명을 고치지 않음. 재서명한 앱은 계속 즉시 종료됨 |
| 다시 재서명하기 | 재서명 자체가 원인이므로 권한만 다시 지움 |
| 앱에 전체 디스크 접근 권한 부여 | 컨테이너 검사를 우회할 수 있지만 키체인 권한이 사라져 로그인 상태는 여전히 문제. 임시 수단일 뿐 |
| 터미널에서 열린다고 해결됐다고 판단 | 터미널 권한을 빌려 실행된 것. Finder / Dock 이중 클릭을 기준으로 판단 |

## AppPorts 1.8.2의 변경 사항

- 컨테이너 디렉토리는 주 프로그램의 샌드박스 여부와 무관하게 심볼릭 링크 대신 [마운트 마이그레이션](/ko/datamigrae/mount-migration)을 사용합니다.
- 우클릭 메뉴, ‘마이그레이션 후 재서명’, 로그인 시 자동 재서명 스크립트 등 모든 진입점에서 샌드박스 앱 재서명을 거부합니다.
- ‘원본 서명 복원’은 개발자 개인 키 없이 원본 앱 전체와 서명, 권한을 복원합니다. 이전 기록은 같은 버전의 공식 원본으로 보완할 수 있습니다.
- 서명이 교체된 앱을 자동 감지해 빨간색 ‘서명 교체됨’, 시작 알림, 우클릭 ‘복구 단계 보기’를 제공합니다.
- 이전 버전의 컨테이너 심볼릭 링크는 계속 ‘연결됨’으로 인식하고 ‘복원’을 사용할 수 있습니다. 컨테이너의 ‘정리’와 ‘다시 연결’은 심볼릭 링크 재생성을 막기 위해 비활성화합니다.
- 기존 방식에 이미 의존하는 사용자를 위해 **클래식 데이터 마이그레이션 모드**를 남겼습니다. 기본값은 꺼짐이며 켜기 전 위험 확인이 필요합니다. [설정](/ko/settings#classic-data-migration-mode)을 참고하세요. 외장 드라이브가 APFS가 아니라면 컨테이너 데이터를 이 Mac에 두는 것을 권장하며 이를 위해 클래식 모드를 켤 필요는 없습니다.

이미 재서명한 앱은 AppPorts를 업데이트해도 자동 복구되지 않습니다. 위 단계에 따라 처리해야 합니다.

## 자주 묻는 질문

### 채팅 기록을 잃게 되나요?

아닙니다. 재설치는 컨테이너 데이터에 영향을 주지 않으며 앱은 기존 데이터를 계속 읽습니다. AppPorts도 전체 과정에서 데이터를 삭제하지 않습니다.

### 데이터를 복원했는데도 열리지 않아요

서명이 아직 복구되지 않았기 때문입니다. 데이터 복원과 재설치는 서로 독립된 단계이며 둘 다 필요합니다. [복구](#복구)를 참고하세요.

### WeChat만 이런가요?

반드시 그렇지는 않습니다. 같은 27에서 재서명한 QQ Music은 정상적으로 열립니다. 현재 증거는 시스템에 이전 서명의 권한 기록이 있는지가 중요함을 보여줍니다. 미리 판단할 수 없어 서명이 교체된 모든 앱을 확인 대상으로 나열합니다. [업그레이드 전 확인](#업그레이드-전-확인)의 스크립트로 전체 목록을 볼 수 있습니다.

### AppPorts가 데이터를 손상시켰나요?

아닙니다. 데이터는 온전합니다. 다만 문제의 직접적인 원인은 이전 AppPorts의 재서명 동의 옵션이 맞으며 1.8.2에서는 이 경로를 제거했습니다.
